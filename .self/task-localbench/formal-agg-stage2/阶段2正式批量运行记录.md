## 关键修正与最终口径

- DeepGEMM 预编译曾在 smoke 中开启验证，`SGLANG_JIT_DEEPGEMM_PRECOMPILE=1` 会触发多个 GEMM 形状的 DeepGEMM warmup，单个小用例也会引入数分钟级固定成本；该成本明显高于保留首层冷启动后的采集成本，因此正式批量默认关闭 DeepGEMM 预编译。
- 正式批量保留 `warmup-runs=1`，但 warmup 采用与 formal 相同长度、不同 token id 的 mixed workload。这样可以预热调度/JIT 路径，同时避免 SGLang radix cache 命中 formal 请求导致 prefill 主体 token 被缓存掉。
- `nsys` profile 触发条件收紧为 prefill rid 前缀 `formal-prefill`，避免捕获 decode 请求初始 prefill 形成的非目标 MIXED batch。
- 正式批量统一使用 6 层，`attention_backend=auto`，`cuda_graph=off`，`piecewise_cuda_graph=off`，`chunked_prefill_size=8192`，`max_prefill_tokens=16384`，对齐 AIC `run_agg` 中单一 isl/prefix 应用于所有请求的简化口径。
- 正式结果已归档到 `bench_data/h100_sxm/sglang/v0.5.9/deepseek_v3_mla/raw_runs/` 与 `bench_data/h100_sxm/sglang/v0.5.9/deepseek_v3_mla/agg_csv/`。
- 正式 8 个用例的汇总表为 `bench_data/h100_sxm/sglang/v0.5.9/deepseek_v3_mla/agg_csv/formal_uniform_agg_summary.csv`。
