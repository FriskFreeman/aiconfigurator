## 目前结论更新

- `prefill` 独立实例在 `PCG off` 时可以正常启动。
- 在 `sglang:v0.5.9` 下，DeepSeek-V3 dummy `5` 层的独立 `prefill` 实例，至少在当前两种 backend 入口下：
  - `triton`
  - `auto`（实际落到 `fa3`）
  都无法成功完成 `piecewise cuda graph` 初始化。
- 因此当前更像是 `DeepSeek MLA + prefill PCG + torch dynamo/compile` 这一组合上的兼容性问题，而不是单纯某个 backend 参数写错。
- 当前 host 脚本也已修正：
  - 结果判定不再只看 docker 退出码，也会结合 `status.json/stage.txt`
  - 容器输出文件默认按宿主用户 UID/GID 写入，避免再产生新的 `root:root` 文件

## 0.5.12 结论

- `0.5.12` 相比 `0.5.9`，DeepSeek-V3 prefill PCG 情况确实发生了变化。
- 变化不是“全部修好”也不是“全部仍坏”，而是出现了 backend 分化：
  - `triton`：已可成功完成 prefill PCG 初始化与退出
  - `auto`：仍失败，而且失败原因已经不同于 `0.5.9`
- 因此当前可以初步判断：
  - `0.5.9` 中那条 DeepSeek MLA + PCG 的老 Dynamo 失败路径，在 `0.5.12` 中至少不再以同样方式出现
  - 但 `auto -> fa3` 这条新版本默认路径下，DeepSeek-V3 dummy `5` 层的 prefill PCG 仍存在问题
