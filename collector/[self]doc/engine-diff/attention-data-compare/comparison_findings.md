## 主要观察

1. Context 在 A100 到数据中心 Blackwell 的多数匹配 shape 上，SGLang latency 更低；RTX PRO 6000 是明显例外，BF16 和 `BF16 tag + FP8 KV` 上 TRT-LLM 更占优。
2. 显式 FP8 context FMHA 在 RTX PRO 6000 上反向变为 SGLang 中位更快（TRT/SGL=1.712），说明 SM120 的 SGLang Triton 路径与 TRT-LLM FP8 FMHA 路径不能由 BF16 结果外推。
3. Generation 呈架构分段：A100/L40S 的 TRT-LLM 更快；H100/H200 BF16 近似持平而 FP8 KV 的 TRT-LLM 明显更快；数据中心 Blackwell 上 SGLang 更快；RTX PRO 6000 接近持平。
4. 未匹配 shape 主要不是数据 join 错误，而是 TRT-LLM 独有的 head_dim=64、window=128、部分 head_dim=256，以及两端不同的硬件过滤和历史采集完整度。
5. 这些是 collector 路径结果，不是纯 CUDA FMHA/XQA kernel 排名。两边的 RoPE、QKV dtype 对齐、KV 写入、runtime wrapper 和 graph capture 边界不同。
