# FA 模型硬件配置与生产使用指南

## 1. v2 配置原则

最终模型只接收会进入公式的硬件数值，不再接收产品身份和软件身份：

```text
已删除 name
已删除 vendor
已删除 architecture_family
已删除 backend_family
```

原因是这些字符串本身不能推导 tile、split、overlap 或效率。将其用于自动路由会把命名约定误当成模型事实，也会增加前端和配置维护复杂度。

FA2/FA3 现在由调用方显式指定，默认 FA2。经验预测由 `standard/high/low` 显式选择，默认 standard。

产品名称、厂商、来源、backend 版本等元数据仍然重要，但应由 AIC systems、资产数据库或调用端维护，不属于该算子数值模型的输入 schema。

---

## 2. 硬件必填字段

| 字段 | 单位 | 进入的模型部分 |
| --- | --- | --- |
| `sm_count` | 个 | CTA并行效率、split和task waves |
| `clock_hz` | Hz | decode task-service |
| `shared_memory_per_sm_bytes` | byte | 自动Br/Bc |
| `l2_capacity_bytes` | byte | 结果记录，v2暂不建容量命中模型 |
| `l2_bandwidth_bytes_s` | byte/s | L2资源时延 |
| `hbm_bandwidth_bytes_s` | byte/s | HBM资源时延 |
| `matrix_peak_flops` | FLOP/s | 各dtype QK/PV时延 |
| `vector_peak_flops` | FLOP/s | softmax/reduction时延 |
| `exp_flop_equivalent` | FLOP/exp | exp等价工作量 |

除 `schema_version` 和 `matrix_peak_flops` 的 dtype 键外，硬件内容全部是数值。

---

## 3. 字段获取方法

### 3.1 SM/CU 数

使用产品实际激活的计算单元数量，而不是完整 die 上限或多卡总数。

它影响：

```text
parallel_efficiency = min(1, CTA_count / SM_count)
N_task waves        = N_task / SM_count
split target        = ceil(SM_count / base_CTA)
```

国产 GPU 可把同等级独立调度计算单元映射为 `sm_count`，但需要确认一个模型 task 是否确实以该单元为服务粒度。

### 3.2 Clock

优先顺序：

1. 目标 kernel 的有效运行频率；
2. application clock；
3. 持续时钟；
4. boost clock；
5. 工程估计。

Matrix/vector peak 已直接输入，不由 clock 重算。clock 主要作用于：

```text
t_task = N_task / SM_count * task_cycles / clock
```

如果只有 boost clock，decode profiled 结果可能偏乐观。

### 3.3 Shared memory

填每个 SM/CU 可用于 kernel tile 的本地 SRAM 抽象。需要区分：

- 统一 L1/shared 总容量；
- programmer-visible shared memory；
- 单 CTA 动态 shared memory 上限；
- 编译后实际分配。

v2 只将容量用于简化 tile heuristic，并把 block 上限限制为 128。容量相同不代表 register、bank 和 kernel recipe 相同。

### 3.4 HBM bandwidth

使用单卡 aggregate byte/s：

```text
TB/s -> value * 1e12
GB/s -> value * 1e9
```

不要使用 bit/s、NVLink 带宽或多卡汇总值。

### 3.5 L2 bandwidth

厂商通常公开 L2 容量，却不公开适合 Roofline 的 sustained aggregate bandwidth。

推荐优先级：

1. 目标卡 L2 microbenchmark；
2. 架构资料推导；
3. 同代工程模型；
4. 上下浮动敏感性分析。

A100/H100 示例沿用 LLMCompass 的 5120 byte/cycle 抽象。它不是 NVIDIA 官方持续带宽。

### 3.6 Matrix peak

按 dtype 分开填写 aggregate dense peak：

```json
"matrix_peak_flops": {
  "bf16": 989000000000000.0,
  "fp8": 1979000000000000.0,
  "fp32": 67000000000000.0
}
```

要求：

- 不使用 structured sparsity 的二倍数字；
- 不把 FP8 peak 复用于 BF16；
- 每个待预测 dtype 必须存在；
- FP32 要确认 IEEE FP32、TF32 或 matrix-engine 语义。

缺失 dtype 时工具直接报错。

### 3.7 Vector peak 和 exp cost

`vector_peak_flops` 用于 softmax、online state 和 reduction 的统一等价 roof。不能填写 Tensor Core peak。

真实硬件的 exp、shuffle、reduction 和 cast 可能位于不同管线。只有宏观规格时，可采用架构文档推导的普通 vector 峰值，并通过三档 profiled 结果表达平均效率差异。

`exp_flop_equivalent=35` 沿用当前模型约定，不是 exp 指令的精确 cycle。

## 4. 显式选择 FA2/FA3

### 4.1 为什么不自动选择

架构名称不能唯一决定实际 attention kernel：

- 新架构可能仍运行 FA2 风格 kernel；
- 同一 GPU 可运行 FlashAttention、Triton、FlashInfer 或 TRT-LLM；
- 支持异步 matrix 指令不代表主循环达到 FA3 理想重叠；
- 国产 GPU 的能力无法从 NVIDIA 风格架构名映射。

因此调用端必须根据真实 kernel 选择：

```bash
--algorithm fa2
--algorithm fa3
```

默认 `fa2` 是较保守、语义直白的选择。

### 4.2 判断标准

选择 FA2：

- matrix 与 softmax/vector 主要串行；
- 没有明确的 producer/consumer overlap；
- backend 行为未知；
- 希望采用默认保守结构。

选择 FA3：

- 已确认 kernel 采用 FA3 风格异步流水；
- matrix 和主循环 vector 可显著重叠；
- 用户愿意采用理想 overlap 抽象。

部分重叠可指定：

```bash
--algorithm fa3 --overlap-fraction 0.5
```

`algorithm` 决定默认 overlap，但显式 `overlap_fraction` 优先。

## 5. 三档参数如何使用

默认：

```bash
--estimate-level standard
```

需要偏保守容量规划：

```bash
--estimate-level high
```

需要偏乐观硬件潜力估计：

```bash
--estimate-level low
```

推荐前端一次计算三档，展示：

```text
低位/乐观      low
标准/中心      standard
高位/保守      high
```

三档是参数场景，不是自动判断目标硬件处于哪一档。模型不会根据产品、架构或 backend 替用户选择。

## 6. 新硬件接入流程

### 步骤 1：复制数值模板

```text
configs/hardware_template.json
```

替换全部示例数值。产品名、来源链接和备注放在模板外部的 systems metadata 中。

### 步骤 2：检查量纲

```text
clock                Hz
HBM/L2 bandwidth     byte/s
matrix/vector peak   FLOP/s
capacity             byte
```

### 步骤 3：运行 analytical

```bash
python3 -m fa_roofline \
  --hardware configs/NEW_GPU.json \
  --input examples/shapes.json \
  --algorithm fa2 \
  --mode analytical
```

检查 Br/Bc、split、parallel efficiency、bottleneck 和各资源数量级。

### 步骤 4：显式确定算法

根据实际 kernel 数据流选择 FA2 或 FA3，不根据 GPU 代际自动猜测。若不清楚，保留默认 FA2，并补充 FA3 sensitivity。

### 步骤 5：运行三档

```bash
python3 -m fa_roofline --hardware configs/NEW_GPU.json --input shapes.json --algorithm fa2 --estimate-level low
python3 -m fa_roofline --hardware configs/NEW_GPU.json --input shapes.json --algorithm fa2 --estimate-level standard
python3 -m fa_roofline --hardware configs/NEW_GPU.json --input shapes.json --algorithm fa2 --estimate-level high
```

### 步骤 6：做结构敏感性

至少比较：

- FA2 与 FA3；
- split 1 与 auto；
- GQA reuse 开与关；
- overlap 0、0.5、1；
- L2 bandwidth 上下浮动；
- low、standard、high。

若结论随假设轻微变化就反转，应报告场景范围而不是单点。

## 7. AIC systems YAML 映射

AIC systems 通常能提供：

```text
mem_bw -> hbm_bandwidth_bytes_s
dtype TC FLOPs -> matrix_peak_flops
```

仍需补充：

- active SM/CU；
- effective clock；
- per-SM shared memory；
- L2 capacity；
- L2 bandwidth；
- vector peak；
- exp 等价成本。

AIC 中的产品名、vendor、架构和 framework/backend 字段仍可保留在 systems 层，但调用 FA 模型时只下发数值硬件结构，并另外显式下发 `algorithm` 和 `estimate_level`。

---

## 8. 国产 GPU 使用方法

把硬件概念映射为：

```text
SM -> 独立调度 compute unit/cluster
Tensor Core -> matrix engine
shared memory -> local SRAM/scratchpad
CTA -> workgroup
```

算法计数中的 FLOPs、causal、GQA、online softmax 和 split partial 通常可复用。需要人工确认：

1. kernel 是否 Q-outer/KV-inner；
2. 工作组按 Hq、Hkv 还是 query-head group 调度；
3. GQA reuse 发生在哪一级；
4. split-KV 与归并实现；
5. matrix/softmax overlap；
6. FP8 accumulation、scale 和 cast 路径。

若不能确认，使用 FA2 标准档，并同时给出高位结果。不要通过伪造 `architecture_family` 来触发某种模型，因为 v2 已经删除该路由。

---

## 9. 有少量目标数据后的升级

保持 FLOPs/bytes/task 结构不变，优先校准：

```text
fixed_overhead_us
hbm_efficiency
compute_efficiency
kv_task_cycles
```

不要按 shape 建独立系数表。数据应覆盖长短 KV、大小 batch、不同 Hkv、MHA/GQA、低高并行度和多 dtype。

如果残差按 shape 形成分支，先检查 tile、split、N_task 和 kernel mapping，再调整 eta。

通用三档仍应保留，目标 backend 参数可由上层作为显式自定义 profile 扩展，而不是重新引入产品名自动路由。

## 10. 配置验收清单

- [ ] hardware JSON 不含 name/vendor/architecture/backend；
- [ ] active SM/CU 是单卡实际值；
- [ ] clock 语义明确；
- [ ] HBM/L2 使用 byte/s；
- [ ] matrix peak 是 dense 非稀疏值；
- [ ] 每个目标 dtype 都有 peak；
- [ ] vector peak 不是 matrix peak；
- [ ] shared memory 是 per-SM/CU；
- [ ] FA2/FA3 由调用端显式选择；
- [ ] standard 为默认档；
- [ ] low/standard/high 已形成单调结果；
- [ ] analytical 和 profiled 均完成 smoke test。
